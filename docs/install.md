# Установка Remnawave X

Практическая инструкция к установщику [samur005/remnawave-reverse-proxy-X](https://github.com/samur005/remnawave-reverse-proxy-X) (ветка `main`, версия скрипта `3.8.4-x.2`). Это форк установщика eGames: он умеет поставить как официальный Remnawave, так и редакцию **Remnawave X** с qWDTT.

English version: [install.en.md](./install.en.md).

## Требования

- **ОС:** Debian 11/12 или Ubuntu 22.04/24.04 (скрипт проверяет это при запуске).
- **Права:** root. Рекомендуется свежая система, виртуализация KVM.
- **Docker и Docker Compose** скрипт ставит сам, заранее ставить не обязательно.
- **Домены:** три разных имени, которые указывают на IP этого сервера:
  - панель управления;
  - страница подписки;
  - selfsteal / нода (маскировочный сайт на стороне ноды).
  Подойдут свои домены или бесплатные вроде `panel.<IP>.sslip.io`, `sub.<IP>.sslip.io`, `node.<IP>.sslip.io`, если они реально резолвятся в IP сервера. Для selfsteal-домена нельзя включать прокси Cloudflare: только DNS Only. Все три имени должны быть уникальными.
- **Порты на сервере** (скрипт открывает их в ufw):
  - SSH (22/tcp или тот порт, который слушает `sshd`);
  - 80/tcp (выпуск сертификатов);
  - 443/tcp (HTTPS и Xray);
  - для qWDTT на ноде: **56000/tcp и 56000/udp** (peer), **56001/udp** (WireGuard сайдкара), **56003/udp** (raw).
  Порт клиента `9000` открывать на сервере не нужно: он локальный, на телефоне. Если в панели поменяете порты сайдкара, откройте уже их, а не значения по умолчанию.
- Порт 443 не должен быть занят чужим сервисом.

## Как запустить установщик

На чистом сервере под root:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/samur005/remnawave-reverse-proxy-X/refs/heads/main/install_remnawave.sh)
```

Если GitHub недоступен, зеркало jsDelivr:

```bash
bash <(curl -Ls https://cdn.jsdelivr.net/gh/samur005/remnawave-reverse-proxy-X@main/install_remnawave.sh)
```

Скрипт скачает остальные модули с той же ветки `main`. После первой установки им можно пользоваться короткой командой `rr` (это `remnawave_reverse`).

В меню выберите **«Установка компонентов Remnawave X»**. Варианты:

1. Панель и нода на одном сервере — самый простой путь.
2. Панель и страница подписки.
3. Только панель.
4. Только страница подписки.
5. Добавить ноду в уже работающую панель.
6. Только нода.

Дальше скрипт спросит веб-сервер (NGINX или Caddy) и домены.

## Official или Remnawave X

При первой установке (если редакция ещё не сохранена) скрипт спросит, какие образы использовать:

1. **Официальный Remnawave** — `remnawave/backend:3` и `remnawave/node:latest`. Без панели qWDTT.
2. **Remnawave X с qWDTT** — `ghcr.io/samur005/backend-x:3` и `ghcr.io/samur005/node-x:latest`. В панели появляется раздел qWDTT, на ноде — сайдкар.

Страница подписок в обоих случаях остаётся официальной: `remnawave/subscription-page:latest`.

Выбор запоминается в `/usr/local/remnawave_reverse/edition` (`official` или `custom`). Позже его можно сменить в меню управления панелью: пункт «Переключить Official / Remnawave X». Обычный `docker compose pull` после этого не подменит панель и ноду «чужими» образами: установщик переписывает строки `image:` под сохранённую редакцию. Тег `:3` у `backend-x` следует за линейкой Remnawave X (в том числе сборки вроде `3.4.11-x.6`).

Для работы qWDTT нужна именно редакция Remnawave X (вариант 2).

## Что указать для панели, подписки и ноды

Скрипт попросит три домена, например:

- панель: `panel.example.com` или `panel.203.0.113.10.sslip.io`;
- подписка: `sub.example.com` или `sub.203.0.113.10.sslip.io`;
- selfsteal ноды: `node.example.com` или `node.203.0.113.10.sslip.io`.

Это должны быть разные имена, которые смотрят на этот сервер. Скрипт сверит DNS и выпустит сертификаты Let’s Encrypt. Если IP домена не совпадает с сервером, установка остановится с подсказкой.

## Что будет после установки

В конце скрипт выведет **логин и пароль** администратора и (при защите панели cookie) **ссылку входа**, которая проставляет cookie доступа. Сохраните их сразу: установщик показывает их в терминале и не кладёт в отдельный файл. Без этой ссылки адрес панели может открыть маскировочный сайт, а не форму входа.

После установки:

- панель: `https://<домен-панели>/`;
- подписка: `https://<домен-подписки>/`;
- нода / selfsteal: `https://<домен-ноды>/`;
- стек панели: каталог **`/opt/remnawave`** (`docker-compose.yml`, `.env`, Caddyfile или nginx.conf);
- если нода стоит отдельно: **`/opt/remnanode`**.

Дальнейшее управление — команда `rr`: статус, логи, обновления, CLI, смена редакции.

## qWDTT после установки (только Remnawave X)

qWDTT — отдельный сайдкар на ноде, не инбаунд Xray. Существующие Reality-хосты он не заменяет.

1. В панели откройте раздел **qWDTT**. Включите интеграцию, сохраните VK cookies, сгенерируйте хеши (или включите автоподдержание). В «Назначенные ноды» отметьте те ноды, на которые нужно отправить сайдкар. Пустой список значит «ни одной ноды»: новые ноды сами не подхватываются.
2. «Хост в подписке (запасной)» (`subHost`) — это **не** домен каждой ноды и его не нужно менять вручную при появлении новых нод. Он используется только как запасной peer, если у хоста пустой адрес, а адрес ноды частный.
3. Чтобы в подписке были разные локации, создайте **хосты qWDTT**: «Хосты» → «Новый хост» → тип **qWDTT**. Укажите примечание (имя/локация, которое увидит клиент), одну ноду в поле «Нода (локация)», адрес и порт (по умолчанию 56000). Адрес можно оставить пустым: тогда берётся публичный адрес ноды. Частные адреса вроде `10/8`, `172.16/12`, `192.168/16`, `127/8` в подписку не попадают. Если публичного peer нет, хост в подписку не выдаётся, а в форме будет предупреждение.
4. В internal squad включите флаг qWDTT (или выдайте доступ пользователю вручную). Пользователи такого сквада получат в обычной base64-подписке отдельные строки `qwdtt://` — по одной на каждый подходящий хост, со своим именем и peer этой ноды.

## Обновление и образы

- Обновление установщика и стека — через меню `rr` (управление панелью / обновление). Для редакции Remnawave X подтягиваются `ghcr.io/samur005/backend-x` и `ghcr.io/samur005/node-x`, страница подписок — официальный `remnawave/subscription-page`.
- Образы панели: [ghcr.io/samur005/backend-x](https://github.com/samur005/backend-X/pkgs/container/backend-x). Теги `:3` и `:latest` движутся вместе с линейкой, можно закрепить конкретный, например `3.4.11-x.6`.
- Фронт панели вшит в образ `backend-x` из релизов [samur005/frontend-X](https://github.com/samur005/frontend-X/releases) (zip `remnawave-frontend.zip`).
- Образ ноды: [ghcr.io/samur005/node-x](https://github.com/samur005/node-X/pkgs/container/node-x), обычно тег `:latest`.
- Перед обновлением установщик сохраняет копию compose и `.env` в `/opt/remnawave/backup/update-<дата>/` и умеет откатиться, если подъём не удался.

Код панели, фронта и ноды: [backend-X](https://github.com/samur005/backend-X), [frontend-X](https://github.com/samur005/frontend-X), [node-X](https://github.com/samur005/node-X). Документация оригинального Remnawave: [docs.rw](https://docs.rw/).
